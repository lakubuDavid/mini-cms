Mini CMS works for two kinds of people:

- content editors who manage workspaces, projects, collections, and items in the dashboard
- developers who automate schema changes with `mini-cms` and integrate the public API

## Start Here

- [Dashboard Guide](/docs/dashboard) — Manage content, projects, collections, and API keys
- [CLI Guide](/docs/cli) — Sync schema, generate clients, automate content management
- [Content API](/docs/api) — Public endpoint for reading published collection items
- [Schema API](/docs/api#schema-api-protected) — Protected endpoints for pull/push operations
- [Environment Variables](/docs/environment) — Required configuration for deployment
- [Hosting](/docs/hosting) — Deploy to Vercel, Netlify, or other Nitro targets

## Recommended Path

1. Set the required environment variables in [Environment Variables](/docs/environment).
2. Deploy the app with [Hosting](/docs/hosting).
3. Create a workspace, then organize content into projects, collections, and items with [Dashboard Guide](/docs/dashboard).
4. Generate an API key and connect your local project with [CLI Guide](/docs/cli).
5. Read published content from [Content API](/docs/api).

## Key Concepts

| Concept | Description |
| --- | --- |
| Workspace | Top-level organization containing projects (like an org) |
| Project | Groups related collections (like a client site) |
| Collection | Content type with a schema (like "testimonials") |
| Item | Single piece of content in a collection |
| API Key | Used by `mini-cms` for schema sync (workspace or project scoped) |

## Public vs Schema API

- **Content API**: Read-only, public, cached, returns only published items
- **Schema API**: Protected, requires API key, used for pull/push and CRUD operations
